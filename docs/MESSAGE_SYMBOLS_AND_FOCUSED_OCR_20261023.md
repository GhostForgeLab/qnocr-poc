# 标点、表情与聊天识别优化

## 已实现

- 原结构化规则只允许字母/数字，导致可靠 OCR 输出的纯标点和 emoji 被拒绝。改为按 Unicode Rune 接受字母、数字、标点和符号，支持非 BMP emoji；保留原文字，不伪造未识别符号。
- 桌面端显式启用图像预览：白底气泡或部分独立彩色图像仍须满足左侧位置、可靠灰色买家/完整时间头等规则。无 OCR 正文时显示未识别提示与图像，不推断情绪/含义。其他实验调用默认不启用视觉回退。
- 混合文字/彩色内容可显示预览。预览不进入消息 JSON，最多 40 条/8MB/512像素长边，仅本次运行内存在；模型未收到图像。未识别消息生成的是固定本地核实用语。
- 动画按时间/视觉消息槽位取得稳定标识，避免图像像素变化重复入队；图像原文不写入历史。
- 使用买家候选区域的纵向范围加时间头余量做聊天 OCR，保持全宽、还原 OCR 坐标。确认失败回退完整聊天区，完整历史入口保留。
- 快速识别默认开启：>=8 逻辑处理器时最多 2 个低优先级计算线程，仍关闭忙等；可在千牛连接页关闭回到单线程。商品按需 OCR 保持单线程。

## 验证

- Release 零警告、零错误。
- 1163 项原回归及新增标点/视觉规则检查通过；补充独立彩色表情检查后的定向消息测试共 37 项通过。
- 桌面集成 17 项通过，包括未识别图像即使商品资料齐全也不请求外部模型。
- 贴窗/UI 检查 19 项通过，渲染并目视检查测试用的图片消息预览（无真实买家数据）。
- 同一实际千牛画面：完整聊天 OCR 2349ms；单线程候选区域 2033ms；双线程候选区域 1451ms。单/双线程已确认正文及时间一致。阶段耗时不等于端到端显示延迟，冷启动更慢。
- 该画面完整 OCR 未能确认消息，区域 OCR 确认 1 条；这是单帧观察，不是全面准确率评估。

边界：没有实现所有表情的语义识别，也没有增加自动上传截图。OCR 未识别出来的标点无法靠保留规则补回；透明、单色或特殊布局表情、缺少可靠时间头、低置信度正文仍可能需要人工核对。低置信度文字不会被强行当作可靠文字。
