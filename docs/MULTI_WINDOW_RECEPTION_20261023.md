# 多千牛窗口并行助手

## 使用

在千牛连接页逐个选择窗口、填写对应店铺标识、点击「添加窗口连接」。已有连接无需断开。添加后每个窗口都有独立小窗；设置页保持打开以便继续添加，完成后可「收起设置，显示全部助手」。

已连接列表支持显示某个助手、查看该连接最新画面、断开选中或断开全部。小窗原「退出」改为「断开」，只停止自身。设置页/托盘退出才关闭全部。窗口最小化、移动、关闭只作用于自己的助手。

## 隔离与保留

- `MainWindow` 仅维护共享设置、商品库和连接列表；每个 `ReceptionSession` 独占控件、消息集合、当前买家、商品选择、草稿、回复视图、预览缓存、取消令牌和 `QianniuConnection`。
- 共享 AI/在线知识配置保留，新回复读取已保存配置并覆盖为该连接的固定 SellerId；不会使用设置页此刻正在编辑的店铺作为其他窗口店铺。
- 产品库继续按 SellerId 保存/筛选。同店铺多个窗口共享该店铺产品资料，但当前商品选择与回复状态独立。
- 作用域记录在 `window-bindings.json`；数据在 `windows/<ScopeId>/`，包含独立 context.db、inbox.json、reviews、reply-index。构造控制器时校验目录与作用域一致，消息和回复服务额外校验 WindowScopeId。
- 同一仍存活窗口以 PID、HWND、进程启动时间、标题和店铺定位自己的作用域；进程重启、句柄重用、改绑店铺建立新作用域。历史目录保留，不静默归入另一窗口。
- 原根目录的加密设置、商品库不迁移；单窗口旧历史仍保留原文件，不自动并入某个新窗口。
- 会话修订号拒绝晚到 AI 结果，停止后的事件被丢弃。断开会取消该窗口的采集、商品识别和回复请求，再释放进程/钩子/数据库，不取消其他窗口。

## 资源与验证

- 全应用最多同时执行 2 个重型 OCR 请求；每个原生进程仍是低优先级、每次最多 1–2 个计算线程。模型内存随窗口数增长，不承诺恒定内存。
- 每帧直接验证已绑定 HWND/PID/标题及进程名，避免每个窗口反复扫描所有 AliRender 进程。显示预览只解码选中的连接，异步结果用连接对象与预览版本核对。
- Release 构建零警告、零错误。
- `--multi-window-checks`：20 项通过，含同店/同买家/同消息 ID 隔离、目录防混用、各自商品事实请求、本地并发 HTTP 回复错序、单独断开保留另一窗口草稿，以及两个真实本地 OCR 进程并发识别/单独停止。
- `--dock-checks`：22 项通过，使用两个透明受控 WPF 宿主验证 A 移动/最小化/关闭不影响 B。
- `--self-test`：17 项通过，原有设置加密、商品导入、HTTP 序列化与人工回复流程保持。
- 已渲染并检查两份独立面板的测试数据预览；未以测试数据填充用户真实界面。

受控验收不代表所有真实多店窗口/缩放组合都已覆盖。实际使用仍需为每个窗口选择正确店铺；不同店铺不要填写同一个自定义店铺标识。
