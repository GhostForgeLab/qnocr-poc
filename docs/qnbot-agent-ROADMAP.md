# qnbot-agent 路线图（V1.31 快照）

状态基线：2026-09-28，qnocr-poc 代码提交 ba7f6ddb166cb0179c6b82f2857a77f513e6430f。**V1.31 已完成的是设计和离线 PoC**，不是运行中 qnbot 扩展。以下版本为建议规划和验收门槛，不表示已授权、已实现或已通过。当前事实见 [STATUS](qnbot-agent-STATUS-V1.31.md)。

| 阶段 | 目标与最小范围 | 进入下一阶段前要证明 |
| --- | --- | --- |
| **V1.32：qnbot Agent Extension 小范围接入** | 在 qnbot 增加可关闭的原生消息只读观察桥；用版本化本机 DTO/IPC 交给 .NET 8 Agent；保持原消息链、AI/发送链不变。先只在测试卖家/买家会话 Shadow 运行。 | 身份来源与会话关系有可审计证据；卖家回显/历史/重复被拦截；订阅生命周期、超时、背压、重连和退出清理可验证；回滚开关有效；SentMessages=0。若可信身份无法取得，保持只读观察与人工辅助，不强行升级 Verified。 |
| **V1.33：桌面 AI 助手面板** | 在 qnbot WPF 辅助窗口提供小型 AI 助手入口或受控本机 Console 打开方式，展示当前 Session、Intent、商品/知识状态、预览、编辑/复制/反馈。 | 不抢占 qnbot 原输入框和发送按钮；会话切换时预览不串线；人工操作有审计；默认 Send OFF；桌面入口故障不影响原客服操作。 |
| **V1.34：真实商品运营验证** | 仅选有可核对来源与 SellerId/ProductId 的少量真实商品，走 Draft、人工审核、显式发布、知识查询和人工评价。 | 资料来源、版本、审核者及允许 AI 使用状态可追溯；缺失事实明确显示 Missing；跨店/跨商品隔离；真实问答质量由人工评价。不能把现有合成测试商品当成真实资料。 |
| **V2.0：个人淘宝 AI 客服客户端** | 在上述入口、安全和运营证据成立后，评估桌面客服辅助产品化：稳定运行、权限、状态保留、更新/回滚与实际客服体验。 | 明确用户范围和部署方式；长时间多消息/多店铺稳定性、隐私与审计、故障恢复及人工工作流通过独立验收。自动发送不作为默认能力；若未来提出，必须另立 Verified 身份和单次授权方案。 |

## 当前最优先的下一步

先评审 V1.32 的只读桥接协议与身份门槛，复核 [集成分析](../QNBOT_AGENT_INTEGRATION_ANALYSIS.md)中“原生事件先于 qnbot 安全处理”这一风险。保留现有 Agent Console 作为可回滚的人工辅助入口；不要为了桌面集成提前改写 qnbot Core、MessageEnvelope 或发送流程。

V1.34 的真实商品来源目前未到位；它不应阻挡 V1.32 的技术边界验证，但也不能在没有核对资料时宣称真实商品知识命中。Feishu/Database 等外部知识来源仍处设计选项，是否接入应由 V1.34 使用数据和治理需求决定。
