# 桌面助手输入卡顿与启动窗口调整

2026-10-23：用户反馈后台 cmd 黑窗常驻，助手运行时打字卡顿。

## 调整

- `启动千牛助手.cmd` 原来的 `start /wait` 导致命令行窗口等待助手退出。现转交同名 `.vbs` 并立即退出；直接双击 `.vbs` 不出现命令行窗口。运行时环境变量仍正确传递，启动错误由窗口提示。
- 桌面 OCR 工作进程降为 BelowNormal，Paddle/MKL/OpenMP/OpenBLAS 计算线程限制为 1，OpenCV 线程为 1，OpenMP 使用 PASSIVE、KMP_BLOCKTIME=0。旧离线 OCR 的默认参数不变。
- 原始像素指纹在工作进程计算，空白校验和指纹共用 LockBits 缓冲读取。完全相同的画面只返回 Unchanged 标记，不再压缩 PNG、通过 JSON 传图或重复解析布局。
- 聊天区和会话头部变化才触发聊天 OCR。商品区轮播、顶部工具栏、输入光标或其他买家列表变化不触发；需要处理聊天时仍使用当前同一帧的商品图。
- 活跃时保留用户检查间隔；聊天静止 5 秒后至少间隔 1 秒，15 秒后至少间隔 2 秒。新消息被检查到后恢复活跃频率。空闲后的首条消息可能多等最多约 2 秒才开始识别。
- 仅在千牛连接页显示预览；图片解码在后台，预览宽度限制 1000 像素，最多每秒一次，只允许一个待处理更新。原图查看/导出保持原分辨率。

## 验证与边界

- Release 构建通过，零警告、零错误。
- 最新 `--memory-capture-live-checks` 共 54 项通过，包括黑图/未渲染图拒绝、单像素变化、聊天变化检测、真实 OCR、低优先级、取消回收和无新增截图文件。
- 实际千牛窗口成功取得画面，OCR 14 行、确认 1 条买家消息；不保存原文或图片。
- 实际静止窗口连续 12 次采集全部返回 Unchanged。测试以 500ms 等待连续采样，工作进程平均约 0.223 个 CPU 核心、约 431MB 工作集；这是活跃检查频率下的短时测量，不代表所有场景或整机占用百分比。
- 单线程受控图片 OCR 复用约 1.39 秒（之前多线程约 0.54 秒），以减少前台资源争抢为取舍。大型聊天图仍可能耗时更久。
- 旧 cmd 入口实测退出码 0，约 235ms 返回，助手窗口成功打开。用户实际输入流畅程度还需要在日常打字与消息到达时确认；不宣称已经消除所有卡顿。

不变：API 配置、商品知识、已有消息及人工回复；不自动发送消息、不自动删除旧截图。
