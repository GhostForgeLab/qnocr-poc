# 店铺、业务备份与人工确认学习（第一版）

## 日常使用

在设置窗口左侧打开 **店铺与备份**。已有商品会自动登记固定店铺 ID，原店铺标识仍可用于连接。显示名称可以修改，固定 ID 不变。

新建店铺后点 **用于连接 / 新增商品**。同一店铺换电脑时应恢复业务备份，不要重新创建同名店铺；同名不代表同一个固定 ID。

## 换电脑 / 重装系统

1. 原电脑点击 **导出业务备份**，保存 `.qnbak` 文件。
2. 把该文件复制到另一块磁盘、U 盘或自己的备份空间，不能只留在将被格式化的系统盘。
3. 新电脑打开助手，在 **店铺与备份 → 选择备份并预览** 中选中该文件。
4. 确认新增、冲突数量。默认保留本机冲突项；明确需要覆盖时勾选覆盖选项，再点击恢复。
5. 选择恢复后的店铺，用于连接。本机重新填写 AI / JEV 密钥并绑定千牛窗口。

恢复前需要先断开助手窗口连接，千牛本身不用退出。请先保存未保存的表单。恢复前自动生成一份本机业务备份，位置为数据目录下的 `business-backups`。

备份包含：固定店铺 ID、显示名、商品及核对状态、店铺优惠、资料补充建议与忽略记录、学习建议、已确认经验及启停状态。

备份不包含：API 密钥及其加密值、AI 服务配置、在线知识源密钥、原始聊天库、窗口绑定、截图、日志。新电脑需要重新填写模型连接设置；恢复不改变原电脑已有密钥。

学习建议中有尽量去标识后的问题、原建议与人工回复片段，因此业务备份仍属于私有业务资料，不是发给朋友的空白测试包，也不是诊断日志包。文件有内容校验，但未加密；请自行妥善保管。此版提供手工导出和恢复前自动备份，不会自动上传云端。

## 学习建议

当助手已对当前商品生成建议，并读到同一会话的新人工文字回复时，若回复与原 AI 建议不同，会尝试收集差异。连续的人工文字回复合并为一条样本，等待约 2 秒后用 **AI 设置**中的模型分析。

在 **学习建议** 页面展开条目，可以查看买家问题、原 AI 建议、人工回复、原文依据和建议原因；修改适用问题及确认内容后，点击 **核对无误，确认生效**。不适用的可以忽略，失败或商品变化的可以重新分析。分析结果不会自动写入商品字段。

确认的经验分为商品知识、表达偏好、问题理解；第一版都限定在同店同商品。回复生成及 JEV 核验会收到相同的已确认经验，并仍以结构化商品资料为准。价格、退款、赔付、临时承诺等个案不能直接作为通用经验启用，应到商品资料补充明确的条件和有效期。

经验可以停用。商品事实变化后旧经验暂停参与后续回复，可核对后重新启用。关闭自动收集不影响已确认经验，已确认内容需逐条停用。

第一版只收集新读到且能够可靠配对的文字回复，不回扫全部历史，不把“未采用”直接等同于原建议错误，不训练或修改模型权重。买家、窗口、会话或商品不匹配，历史基线消息、图像、服务错误占位文字、超过 15 分钟的问答间隔等会跳过。未收集不等于确认不值得学习。最多保存 1000 条样本、500 条经验；可清理已忽略片段。

模型分析会发送去标识的问答片段和对应商品资料到已配置服务。去标识会尽量隐藏买家名、手机、邮箱、长编号、链接与可识别密钥，不保证识别所有个人信息；人工确认前应检查原文。任何情况下都不会自动向买家发送消息。

## 实现与验证

- `business.json` 为版本化业务快照；旧 `products.json`、`shop-knowledge.json`、建议缓存首次迁移后原文件保留，不再作为日常读写来源。
- 恢复仅接受固定的两个 ZIP 条目，不解压执行内容；校验大小、摘要、版本、身份引用及重复记录。单次原子替换，预览后资料变化则拒绝恢复。
- 相同固定 ID 合并；相同旧名称但固定 ID 不同的店铺保持独立。凭证配置不参与备份或恢复。
- 待分析、未确认、忽略、停用和失效经验都不送入回复证据。迟到分析不能覆盖人工决定，生成期间经验变化则丢弃旧结果。
- 50 项业务迁移/备份/审核检查，9 项本地 HTTP 与真实消息接入链路检查通过。
- 24 项资料补充建议、21 项双向上下文、38 项桌面集成、23 项自动回复、14 项诊断日志回归检查通过。
- 配置模型的真实接口以完全虚构的清洁问答验证，返回逐字引用人工原文的学习建议；未发送实际商品或聊天。
- Release 构建：0 错误、0 警告；WPF 店铺页与展开审核页已渲染检查。

本轮不更新便携测试包。
