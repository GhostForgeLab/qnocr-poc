# 当前会话恢复与商品识别重试

## 根因

实际桌面 inbox 仍引用旧的 Inactive 会话；SQLite 中同一买家已有新的 Active 会话。Agent 会话默认空闲 30 分钟后失效。旧消息去重只检查 MessageId，忽略相同消息在会话续期后的 SessionId 变化，导致新绑定没有发布/替换到界面。

`AgentContextIntentAdapter` 因此在任何模型调用前拒绝旧会话：`Intent requires a current, isolated Agent session.` 这不是模型返回的意图判断。“历史回复 21:02”也不是本次重新生成的结果。

## 修改

- OCR 发布和 UI 收件箱去重同时检查消息与会话绑定。SessionId 变化时替换旧记录、更新选中会话并保留同店商品选择。
- 自动生成和手工生成前，验证当前窗口、观察到的买家、店铺、来源、消息 ID、时间、文本，以及实时画面绑定。若原会话已经超时，只重新观察当前选中的可见消息，由 Agent 管理器创建/复用 Active 会话，不修改旧会话状态、不迁移旧历史。
- 相同消息 ID 在新会话下不会加载旧会话回复；旧预览和确认记录仍保留。
- 保留底层严格隔离校验，不删除 Active 校验，不延长全局超时来掩盖问题。
- 商品识别发生瞬时画面变化时重试一次。真正切换买家后丢弃结果；识别失败不清空已选商品。

## 验证

- 16 项恢复检查，覆盖空闲超时、当前消息重绑定、旧历史隔离、重复消息更新、手动/自动准备、跨买家/店铺/窗口拒绝、文本篡改拒绝、商品识别重试和重启恢复。
- 用真实两个买家的 SQLite 只读备份和 inbox 快照重放：原绑定均为 Inactive，恢复为新的有效会话，每条上下文只含当前选中的消息。结果目录 `Output/SessionRecoveryReplay/808832a106a94ef094aa5098f68c8636`。不调用外部模型、不修改真实数据库。
- 21 项自动回复、20 项多窗口隔离、37 项桌面集成回归通过。

实际 OCR/窗口识别仍以当前可见买家为准；画面尚未确认时等待确认，不从其他会话补资料。
