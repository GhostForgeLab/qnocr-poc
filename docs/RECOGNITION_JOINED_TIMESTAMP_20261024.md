# 日期与时刻连写导致的买家漏读

## 复现与根因

用户提供截图中，原生 OCR 已识别到买家昵称和“好的”，且置信度均高于 0.99；时间头被识别为 `2026-10-2413:43:08`。原时间表达式要求日期和时刻间有空格，因此该白色买家气泡被标记 `MissingReliableFullTimestampAndBuyerHeader`。两条卖家消息仍被识别，但无法据此建立新的买家绑定。

这张附件包含桌面局部与助手，回放使用其中明确可见的聊天区域，不把整个附件误作完整窗口布局输入。修复前为买家 0、卖家 2、未绑定；修复后为买家 1、卖家 2、绑定成功。用户打开实际千牛窗口后，本机内存检查也得到买家 1、卖家 2、绑定成功。

## 修复

- 保留有空格的日期时间格式，另外接受日和小时均为两位数的明确连写形式。
- 完整年月日时分秒、有效日期/时间、可靠昵称/时间头位置与 OCR 置信度仍然必须满足；不使用截屏时间补齐，不放宽买家唯一性。
- 聚焦 OCR 无法确认买家时，即使已识别卖家消息，也对完整聊天区域重识别一次；仅在获得可靠绑定或更多有效消息时采用结果。
- 日志补充 `RecognitionHeld` 和时间头缺失/身份不唯一/完整区域重识别等固定原因代码，不包含正文。
- 未确认提示说明“昵称或完整时间头尚未确认”，不再一律要求用户打开已经打开的聊天。

## 验证

43 项消息解析检查通过，包括连写、全角、无效日期、缺少秒、模糊边界、低置信度和角色隔离。21 项双向上下文检查及原生 OCR 合成聊天检查通过。实际截图回放与实际窗口内存检查均通过，未调用外部 AI、未保存新的截图或聊天正文文件。

开发回放命令 `--recognition-image-check` 只针对这次附件布局，位于开发检查代码中，不编入便携发布版。已经生成的旧便携 ZIP 没有被覆盖；重新发布时会包含源码修复。
