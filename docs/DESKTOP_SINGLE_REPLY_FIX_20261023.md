# 单条回复与真实会话问题修复

## 实际记录中的根因

- 21:33、21:38 的“尺寸是多少”：实际调用 JEV `jev-1.14.0`，意图为 `PRODUCT_SPEC_QUERY`，资料判定为 `CLARIFY_BUYER`，概率 0.79 / 0.78。旧代码低于 0.80 就改成人工核实，`ModelUsed=false`，未调用回复模型。
- “这是一条还是一盒？”界面保留的是 21:02 的旧核实回复，状态 Copied 且没有人工编辑。旧缓存规则将复制状态当作禁止升级的条件，因此没有执行新版身份澄清。

## 修改

- 取消三选一界面与桌面多候选生成，保留单条编辑框、自动生成、人工复制。
- JEV 初判低置信度进入 `EVIDENCE_FIRST`，仍调用回复模型阅读现有资料，之后核验实际文字。各款尺寸和价格存在时可直接分组回答。
- 新增 `ANSWER_OPTIONS` 分类，明确未选款不等于无资料；允许等价的尺寸乘号、单位及重复尺寸分组。
- 商品身份澄清也先调用已配置回复模型；生成未通过核验时，可引用已核对售卖范围。严格匹配的已标注尺寸可逐字引用兜底，但不能推断内部尺寸、装载或未知款式。
- 缓存带流程版本。旧版本未人工编辑的已复制回复可重新生成，历史记录保留；人工保存修改与正在编辑的草稿不被自动覆盖。
- `reply-assessment.json` 记录实际请求尝试/成功次数、JEV 模型、回复模型、核验、耗时和流程版本。界面一行显示是否调用，悬停查看详情，旧记录标记为历史。
