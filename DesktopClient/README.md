# QN Agent · 千牛客服助手

## 免安装测试包

发布使用根目录 `Build-Portable.ps1 -Version '20261024-test02'`（后续构建使用新版本号），ZIP 输出到 `Output/Distributions/`。测试者完整解压后双击 `QNAgent.exe`；内含 x64 .NET、OCR 模型与本地原生依赖，无需安装 SDK。说明见 `docs/PORTABLE_QUICK_START.txt`。

发布构建设置 `PortableRelease=true`：数据只存于 EXE 同级的 `Data/`，不会向上寻找开发项目；排除开发检查/真实历史回放入口和示例商品；OCR 子程序只接受内部内存工作协议。打包只取全新 publish 输出，附文件 SHA256 清单、依赖许可和空白使用说明，不复制现有 `Output/DesktopClient`。

`QNAgent.exe --portable-checks` 在独立 `SmokeData/` 内进行离线合成验证，覆盖本地运行时、Windows 密钥保护、SQLite、真实中文 OCR、WPF 启动及诊断导出。仅在从 ZIP 解压出的验证副本运行，不要把验证副本或用过的 `Data/` 重新压缩发给其他人。静态审计使用 `python Validation/PortablePackageAudit.py <ZIP路径>`；正常运行仍需测试者自行配置回复模型/JEV 服务并录入商品资料。

这是独立 WPF Windows 客户端，当前可执行文件为 `bin/Release/net8.0-windows/win-x64/QNAgent.exe`。项目根目录的 `启动千牛助手.vbs` 可以双击无黑窗打开，并设置随项目附带的 .NET 运行时。旧 `.cmd` 入口会转交给它后退出。重建并打开使用 `Start-Desktop.ps1`。

## 实际使用

1. 打开并登录各个千牛接待中心。在「千牛连接」点击刷新，选择一个窗口，填写它对应的店铺标识，点击「添加窗口连接」。然后继续选择第二个窗口并添加，无需断开第一个。不同店铺填写各自的标识；同店铺多个窗口可以使用同一店铺标识，仍各有独立会话与回复状态。店铺标识是本地资料作用域，不冒充平台核验 ID。
2. 在「AI 设置」配置 API 基础地址、模型、Key，保存后点击测试。支持 OpenRouter 与兼容 Chat Completions 的服务；本机服务可使用 loopback HTTP，远程服务须 HTTPS。Key 通过当前 Windows 用户 DPAPI 加密，复制到另一账户或机器不能直接解密。
3. 在「商品与知识库」新增或导入商品，店铺标识须与连接配置相同。填写商品 ID、名称、资料来源和知识，核对后允许 AI 使用并保存。修改资料会取消原核对状态。
4. 小窗默认显示当前买家最新的已识别问题。「最近 10 条对话」可查看当前买卖双方已识别消息，按顺序标明角色。读取当前买家并识别/选择已核对商品后，仅新买家消息触发自动生成一条建议。首屏历史只载入，可手工生成。可直接修改，再点击「确认并复制」，由客服在千牛粘贴发送。可取消勾选“买家新消息时自动生成建议”暂停本窗口自动处理，或手动点击“重新生成回复建议”。

每个已添加窗口旁都有自己的会话助手，跟随该窗口移动；最小化、恢复、关闭只影响对应小窗。连接管理列表可选中某一窗口查看其采集预览、显示助手或「断开选中连接」，也可「断开全部」。添加完成后点击「收起设置，显示全部助手」。

商品保存成功后会清空并收起编辑区，继续录入点击“新增商品”。修改时先选中列表条目，再点击“编辑选中商品”（也支持双击条目）；单击仅选中，不会自动覆盖正在编辑的表单。保存失败时保留输入，新建商品不能静默覆盖同店铺同 ID 的现有记录。

“确认并复制”支持已确认回复的复制重试和再次复制。剪贴板写入会持久化并读回核对，失败不会标记为复制成功。已确认或复制的文字再修改时，会创建独立的人工修改版本，保留原记录，修改后的版本需重新确认。此操作仍不会向千牛自动发送。

桌面回复使用 JEV → 回复模型 → JEV 核验的流程。首次 JEV 请求同时判断意图和资料充分性。初判只作参考，低于门槛进入 EVIDENCE_FIRST，仍调用回复模型读取完整资料；不能把分类不确定当作无资料。没有选款但各款尺寸/价格已列出时，先按款分组回答，再询问具体款式。生成后的每个事实还必须经第二次 JEV 判断支持，高置信度有依据的回复正常显示；SUPPORTED 且概率至少 0.65、confidence 至少 0.50 的文字以人工核对草稿展示。UNSUPPORTED、UNCERTAIN 与更低置信度文字仍不作为回复。这些是初始工程阈值，不是正确率保证，应根据后续真实问题评估。

缺内部尺寸不能据外尺寸判断包装适配；已知价格但未知适配可以仅回答价格，剩下核实；缺款式等买家条件时先追问。JEV 不可用、返回无效结果、核验失败或不确定时，回到固定核实回复，不静默降级为关键词分类。无法识别的纯图像消息仍直接询问文字说明，不上传图片。

AI 设置新增 JEV 接口、模型和独立 API Key，默认使用 `https://api.typesafe.ai/v1/systemone`、`jev-latest`，密钥通过 Windows DPAPI 加密；未保存独立 Key 时可读取 `TYPESAFE_API_KEY`，保存设置会将该环境密钥加密存入本机。回复继续使用原来的 AI 地址、模型和 Key。当前窗口识别到新的买家消息且商品已核对时自动运行，也可手动重新生成；卖家消息不触发。单条普通建议使用一次 JEV 意图/资料判定、一次回复模型请求和一次 JEV 回复核验。请求可取消，单次 JEV 超时为 25 秒；服务限流最多重试一次。

输出使用纯文本，去掉 Markdown 星号；数字间乘号保留为“×”。仅“烟盒”可以包含“烟”字，其他带该字的表述最多重写一次，再失败则改为固定核实回复。人工修改后的回复也在保存/复制前检查用词。旧建议需点击“生成回复建议”重新走新流程，旧的人工确认记录不会被改写。

每条预览同目录的 `reply-assessment.json` 记录 JEV 模型、意图、资料判定、核验结果和回退原因。界面区分资料缺失、需要追问、部分回答、JEV 不可用、回复核验未通过等状态。受控回归用 `--jev-checks`；`--jev-live-checks` 使用虚构资料验证真实 JEV；`--jev-reply-live-checks` 额外调用当前已配置的回复模型测试完整链路，产生少量 API 用量，不使用真实买家消息。

小窗「设置」打开共享设置并选中自己的连接；「收起/展开」仅影响自己；小窗「断开」仅断开自己。托盘可显示全部助手、打开连接管理或退出全部。仍有连接时关闭设置窗只是隐藏；全部退出请使用设置页或托盘的退出按钮。AI/在线知识设置继续共享，新请求读取当前设置；各窗口的店铺绑定不会跟着设置页正在编辑的店铺标识变化。

贴窗机制参考 `D:/CodexWork/qnagent/qnbot/src/Bot/AssistWindow/WndAssist.AttachedPerformance.cs` 的低开销方案：只移动助手自己的窗口，使用目标窗口事件跟随、40ms 合并突发事件、5秒几何兜底，不抢焦点、不全局置顶、不改变千牛大小。右侧无空间时贴左侧；千牛最大化时放在屏幕内侧。旧项目文件未修改，也未引入旧项目的自动发送逻辑。

聊天正文变化且买家标题与切换标识未变时，保留问题、商品、意图和草稿，仅暂时暂停操作等待确认。明确切换买家、最小化、断开或身份无法确认时，再撤下旧买家内容；重新确认后展示对应会话。买家切换仍受现有采集/OCR 延迟影响。切换期间返回的异步 AI 结果不会覆盖新买家界面。编辑中的非空草稿按消息在本次运行内保留；「保存草稿」仍写入原有人工回复记录。

首次看到的买家消息会作为可见历史载入，并明确标记；首屏历史不自动调用模型，不遍历旧问题；只有新识别到的买家消息可触发自动建议。后续消息复用现有去重和 Agent Session/SQLite 上下文。不同买家、店铺的资料不混用。当前不能后台读取未显示的会话、订单或平台实时库存。

## 本地和在线知识

商品编辑支持可增删的规格、优惠和问答条目：

- **商品规格与价格**：一个商品 ID 下逐条添加款式名称、价格（人民币元）、规格差异 / 容量 / 适用说明。价格最多两位小数，留空表示待核实，规格名称不可重复。
- **商品单品优惠**：仅保存在当前商品中。每条填写名称、适用规格、门槛与减免规则、有效期、叠加规则。未知条件明确写“待核实”。
- **店铺优惠**：填写店铺标识并点击“载入该店铺优惠”，编辑、核对并独立保存。存于共享数据目录的 `shop-knowledge.json`，只供对应店铺使用；同店多个商品和接待窗口共用，不随全局设置正在编辑的店铺而串用。商品 JSON 导入、导出、同步不包含或覆盖店铺优惠。
- **常见问答**：支持新增、编辑、删除问题和答案，也有“不同规格有什么区别”“适合什么场景使用”等快捷问题。未填完整的条目需要补全或删除才能保存。

旧版 `Capacity`、`CurrentPrice` 和 `Notes` 原文仍保留在通用说明及其他文档中，不自动猜测拆分。新增、编辑、删除商品条目会取消商品核对状态；店铺优惠有独立核对状态。AI 请求包含分开的规格价格、单品优惠、店铺优惠和问答，并要求在规格不明、规则冲突、有效期或叠加条件不明时先核实。优惠规则是资料，不是平台实时验券或自动结算结果。

本地批量导入接受如下 JSON 数组，在线同步接口也需返回同样结构。`Approved` 在导入时一律降为 false，需要在客户端重新核对。导出按钮生成当前全部商品的同格式文件。

```json
[
  {
    "SellerId": "与你的千牛连接设置一致",
    "ProductId": "填写真实数字商品ID",
    "Name": "真实商品名称",
    "Material": "已核对的材质",
    "Capacity": "已核对的规格或容量",
    "CurrentPrice": "价格及适用条件",
    "ShippingTime": "发货说明",
    "ReturnPolicy": "售后政策",
    "CustomizationPolicy": "定制说明",
    "Variants": [
      { "Name": "款式 A", "Price": 298.00, "Details": "已核对的规格区别" },
      { "Name": "款式 B", "Price": null, "Details": "价格待核实" }
    ],
    "Promotions": [],
    "Faqs": [ { "Question": "适合什么场景使用？", "Answer": "已核对的适用场景和限制" } ],
    "Notes": "补充资料、FAQ 或商品知识文档",
    "Source": "资料来源",
    "Approved": false
  }
]
```

该例为字段说明，不能不修改就作为真实商品导入。TXT/Markdown 可以载入当前商品的备注区，核对后保存。JSON 文件/响应最多 2 MB，最多 2000 条商品；单商品备注最多 12000 字，单项资料最多 2000 字。

`Variants`、`Promotions`、`Faqs` 可省略（兼容旧 JSON），但不能为 null。每个商品最多 200 个规格、100 条问答、50 条优惠。优惠条目字段为 `Title`、`AppliesTo`、`Rule`、`Validity`、`Stacking`，均为必填文本。界面和保存检查可用 `QNAgent.exe --knowledge-editor-checks`，受控 HTTP、隔离及兼容检查用 `--self-test`、`--multi-window-checks`。

在线知识源填写 JSON HTTPS URL，可另填 Bearer Token；不在 URL 查询参数里放密钥。同步会替换相同 SellerId/ProductId 的本地记录并撤销其旧核对状态；不会修改线上数据。当前没有飞书、语雀、Notion 等专有连接器，也没有向量检索。在线接口的 redirects 不自动跟随，以免认证信息被转发。

## 数据和运行限制

默认数据在项目 `Output/DesktopClient/`。原加密设置和商品库保持原位置；新增 `window-bindings.json` 记录窗口作用域。每个窗口的上下文 SQLite、消息、草稿/回复索引与人工回复放在 `windows/<ScopeId>/`，即使两个窗口买家名及消息 ID 相同也不共用文件。商品库按店铺过滤，商品选择在各个小窗独立维护。

同一个仍在运行的千牛窗口重新连接可复用自己的作用域；千牛进程重新启动、句柄被重用或重新绑定店铺时建立新作用域，旧记录保留，不静默并入另一个窗口。原单窗口历史文件仍保留在原目录，不自动混入新窗口记录。关闭助手停止所有采集，保留已有设置、商品及各作用域记录。

每个窗口有独立的取消令牌、OCR 进程、变化缓存和回复请求。全应用同时最多运行两个重型 OCR 请求；采集直接校验已绑定 HWND/PID/标题，不再每帧扫描所有千牛进程。多开仍会增加模型内存占用，不表示后台能读取没有显示的聊天会话。

桌面客户端现在使用内存采集：完整画面、裁剪区域和 OCR 请求/结果通过当前用户专用管道传递，不建立 `captures` 目录，不自动保存 PNG 或逐帧 JSON。预览只保留最新画面，「查看原始画面」也不写文件；只有点击「导出当前截图」选择路径后才落盘。以前版本保存的截图仍保留，可在断开后通过「打开数据目录」自行管理；旧实验命令的证据保存方式不变。

活跃时默认每 500 毫秒检查画面（可设 250–2000 毫秒）；聊天无变化 5 秒后至少间隔 1 秒，15 秒后至少间隔 2 秒。点击目标千牛的买家列表会立即唤醒采集并撤下旧买家内容，在短暂的 1 秒内加快稳定性采样，不等待空闲计时；鼠标钩子不读取按键、不注入输入、不记录轨迹，安装失败时仍保留定时采集。聊天区或会话头部变化后，等画面稳定 300 毫秒再识别；持续动画最多等待 1500 毫秒。输入光标、顶部工具栏和商品区单独变化不触发聊天 OCR。

每次连接保留最多 24 个精确聊天区+头部画面指纹对应的 OCR 结果，切回完全相同的画面直接复用，只有文本结果在内存中缓存。新消息/不同头部不能命中旧结果。新 OCR 完成后先复核当前画面，切换中的过期结果不展示。

消息展示不再等待商品栏 OCR。商品可手动选择，或点击小窗「识别当前商品」按需识别新截图中的商品；识别前后校验会话，变化时拒绝选用结果。按需商品识别使用独立、低优先级单线程工作进程，结束后释放，不阻塞买家切换。窗口最小化时暂停，恢复后重新校验。

OCR 工作进程使用低于正常的优先级，关闭空闲忙等。「快速识别」默认开启，在至少 8 个逻辑处理器的电脑上最多使用 2 个计算线程；关闭后或较少核心的电脑使用单线程。修改后保存并重新连接生效。商品按需识别仍为单线程。静止完整画面只比较原始像素指纹，不重复压缩 PNG/传图/解析布局。整窗预览仅在连接页后台解码、最多每秒一次。

聊天 OCR 优先处理左侧买家气泡/图像及上方时间头所在的纵向区域，保留原横向宽度和坐标；不能确认消息时回退完整聊天区。聊天很长或缺少可定位气泡时不保证加速。

标点与表情：已被 OCR 可靠识别出的 `？？？`、`……`、Unicode emoji 等不再因缺少字母或数字被丢弃，仍要求可靠买家、完整时间戳和左侧气泡证据。桌面端对符合位置/时间规则但 OCR 没读出正文的白底气泡、部分独立彩色表情提供图像预览，显示「消息内容未识别」。混合文字与彩色图像也提供预览。原图预览只是展示，不代表模型理解了表情含义；透明/单色/特殊布局或缺少可靠时间头仍可能漏检。

消息图像最多保留 40 条且合计不超过 8MB，只在内存中，缩略图长边最多 512 像素，不自动落盘或上传。历史文字记录保留类型与未识别提示，重启后原预览不可恢复，重新看到对应会话可补回。动画按时间与消息位置去重，避免每一帧都成为新消息。「生成核实回复」对未识别消息只返回本机固定询问用语，不调用视觉模型。

采集仍使用已有 `PrintWindow`，尚未接入 WGC。每次连接使用一个可取消、可超时终止的工作进程，OCR 模型首次使用后复用；截图 20 秒、OCR 45 秒超时会停止连接并释放进程。消息记录使用 `memory:<id>` 作为采集标识，不是图片路径。没有永久截图证据，排查问题时请手动导出。

客户端复用旧截图/OCR、身份归一化、上下文、规则意图和人工预览服务；新增桌面范围内的真实商品库与可配置 HTTP 模型连接。旧实验 Preview 链保持原行为。真实外部模型、完整多买家与长期生产运行仍须使用实际环境验证。

验证命令：在正常 Windows 用户环境运行 `dotnet QNAgent.dll --self-test`，覆盖 DPAPI、设置持久化、商品导入核对状态、跨店隔离、实际本地 HTTP 请求/同步、文本知识与原人工审阅接口。受控 HTTP 成功不等于真实外部 AI 已连通。

`dotnet QNAgent.dll --memory-capture-checks` 验证变化/稳定检测、旧设置兼容、内存裁剪、真实 OCR 模型复用、取消退出及不新增截图文件；`--memory-capture-live-checks` 另外读取一个已显示的千牛接待窗口，验证内存捕获和识别，只报告数量与耗时，不保存画面或聊天原文。

模型请求协议参考 [OpenRouter Chat Completions](https://openrouter.ai/docs/api/api-reference/chat/create-a-chat-completion)。

## 单条回复、缓存与调用记录

会话助手已取消可选方案，只保留一个回复编辑框。新买家消息在已核对商品确定后自动生成；可以暂停自动生成或手工重新生成。500 毫秒合并等待避免画面重复刷新反复调用。切换买家、消息、商品会取消旧任务，生成期间的人工输入不会被覆盖。

缓存带有流程版本 `dialogue-ten-turns-v4`。旧版本未人工修改过的回复，即使此前已复制，也会在当前会话按新版自动重新生成；原确认/复制记录保留。历史人工修改回复和当前正在编辑的草稿仍保留，需手动重新生成。新版本同消息同知识版本的结果继续去重。

JEV 判断“不确定”不再直接阻断回复模型。分类置信度与回复事实依据分开处理：模型先尝试回答有依据的部分，再询问缺失条件，生成后核验实际文字。已核对的售卖内容和严格匹配的尺寸原文可作为最后的引用兜底，尺寸引用不得用于推断内部尺寸、包装适配或未提供的款式。

每条回复的 `reply-assessment.json` 增加 PipelineVersion 与 Calls：JEV 判定是否尝试/成功、实际 JEV 模型、回复模型配置名、回复请求尝试/成功次数、核验是否完成、开始时间和总耗时。界面单行显示“JEV 已调用 / 回复模型已调用”或明确失败/未调用，悬停可查看详情。旧记录标记为历史回复，不再用“已复制”掩盖未重新生成。

`--real-catalog-replay` 会在明确授权后，用本机真实商品资料和指定问题调用已配置的两个服务，替换店铺和买家标识，在独立 Output/RealCatalogReplay 目录保存结果；不写真实会话、不发送消息。

服务故障不属于知识缺失：回复请求失败后，建议框留空并提示重试，不再填充固定核实话术。HTTP 请求最多重试一次，认证错误等不盲目重试。日志包含 HTTP、结束原因、实际返回模型、错误代码和重试原因。详见 docs/DESKTOP_REPLY_RESILIENCE_20261023.md。


会话恢复：同一消息在新的 Active 会话中重新出现时会更新 SessionId，而不是当作重复消息忽略。生成前验证当前窗口、买家及原消息；过期会话仅以当前可见消息重新建立有效上下文，不恢复旧历史、不绕过隔离检查。商品识别因短暂画面变化中断时自动重试一次；切换买家则丢弃结果。可用 --session-recovery-checks 测试，--saved-session-replay 在真实数据库只读副本上重放已报告的两个买家绑定，不调用外部服务。

## AI 资料补充建议（第一版）

保存商品成功后，右侧独立建议区会异步调用「AI 设置」中的回复模型检查资料缺口。此检查使用独立提示词，不经过客服回复的 JEV 意图与核验流程；仅发送当前商品已保存的字段、规格、FAQ、文档、同店优惠和已忽略问题，不包含买家聊天或其他店铺资料。检查失败不影响保存，可点击“重新检查已保存资料”。浏览已保存商品只读取已有报告，不自动批量调用模型。

每次最多 8 条建议，标注售前/使用保养/售后、优先级、缺失/部分覆盖/需澄清、对应填写位置。建议仅包含问题、缺口说明和补充方向，输出 schema 不允许答案字段，也不自动写入已核对知识。模型仍可能误判资料覆盖，可由商家忽略或修正。

- **去填写**：打开对应商品并定位字段/规格/优惠/FAQ，不填写内容；同商品未保存输入会保留，其他商品有未保存编辑时阻止覆盖。
- **加入问答**：只加入问题，答案留空，取消编辑区的核对状态；重复问题不重复添加。需人工补充答案、核对并保存才进入商品资料。
- **忽略**：按店铺和商品记住不适用主题，后续检查继续抑制，可在“已忽略 / 不适用”恢复。

报告和忽略状态保存在 `Output/DesktopClient/knowledge-advice/` 的独立文件，文件名使用店铺和商品组合的哈希；不会进入客服模型的商品资料，也不随商品 JSON 导出。商品事实、相关店铺优惠和模型配置构成内容版本；重复保存相同内容复用报告，切换商品或旧请求晚到不会覆盖当前建议。

验证命令：`--knowledge-advice-checks`（模拟模型与真实 WPF 编辑流程）、`--knowledge-advice-http-checks`（本机 HTTP）、`--knowledge-advice-live-checks`（虚构商品调用已配置模型，不使用真实商品或买家数据）。
## JEV 意图卡片与图标

当前消息下方新增“JEV 意图分析”：展示买家当前沟通目的、把握程度和回复方向。低把握显示“需确认”，不将模型推测当作真实心理；没有候选回复区，仍保留一条可编辑建议。JEV 初判完成即显示，切换买家或商品会清空旧卡片。

“好的”“谢谢”等纯确认不再默认继续介绍商品；“好的，多少钱？”仍回答后面的实质问题。可用 --intent-card-checks 检查 UI 和图标，--intent-purpose-live-checks 使用虚构商品测试真实 JEV 与回复模型。

应用窗口、任务栏和托盘使用统一聊天气泡图标，源图与多尺寸 ICO 在 DesktopClient/Assets/。详见 docs/DESKTOP_INTENT_CARD_ICON_20261024.md。
## 买卖双方对话上下文

桌面识别当前浅色千牛界面的左侧买家白色气泡和右侧卖家蓝色气泡，均要求可靠的发送人/完整时间头，角色不确定的内容留作未确认信息。消息带 buyer/seller 角色，同一句话由不同角色发送也不会混作一条。买家身份只从买家证据读取，不能使用卖家昵称；仅卖家消息可见时，必须与此前确认的买家标题指纹和切换版本完全一致，才能沿用该买家绑定。

JEV 和回复模型使用当前买家问题及之前最多 9 条已识别的双方消息，总计最多 10 条，并限制总字数。旧的非桌面调用保持原来的上下文长度。历史卖家回复用于理解接话和避免重复问答，不自动变成已核对的商品事实。

卖家回复只追加上下文，保留当前问题、商品、意图和手工草稿，不重新生成建议；若旧建议仍在生成，会取消，后到结果不能覆盖手工内容。普通正文变化不清空界面，但在确认身份期间暂停操作；标题变化或实际切换买家仍切换隔离会话。

自动触发资格只来自本次运行中新识别到的买家消息。首屏历史、卖家消息、商品重选或知识修改本身都不触发自动回复；当前问题可使用“重新生成回复建议”手工处理。最近对话区标记买家/卖家，最多展示 10 条。

测试：--dialogue-checks 验证双向结构化、UI 更新、上下文和隔离；--dialogue-native-checks 用合成聊天验证实际原生 OCR；--dialogue-live-capture 仅在本机内存读取当前可见千牛窗口，输出角色数量，不保存聊天内容或调用外部模型。
## 日志与诊断

左侧新增“日志与诊断”，支持错误/警告/信息/调试级别（即时保存）、打开日志目录、按最近24小时/7天/全部已保留导出 ZIP。默认信息；测试复现前可切调试。日志目录为共享数据根的 diagnostics/，按大小轮换，最多10段、每段约2MB、保留7天。

诊断包只包含技术信息和显式字段摘要，不直接复制原始文件；排除明文/加密密钥、聊天正文、模型回复、截图、姓名/账号、完整网址、商品资料和数据库。日志级别不影响业务流程，导出不会发送给任何人。启动失败时可用 `QNAgent.exe --export-diagnostics 输出路径.zip` 导出最近7天。

导出使用 UTC/带偏移时间戳；最多10000条事件和1000份调用摘要，省略数量写入 manifest。调用摘要可能包含人工修订关联，不作为计费用量统计。

验证使用 --diagnostic-checks。发给朋友的操作说明在 docs/TESTER_LOG_GUIDE.md；分发程序不要带自己的 Output/DesktopClient 数据目录。
